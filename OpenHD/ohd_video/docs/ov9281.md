# OV9281 on Raspberry Pi 4 / 5

The OV9281 is a 1 MP monochrome global shutter sensor. OpenHD drives it
through libcamera, like the other RPi CSI cameras:

- Camera type `X_CAM_TYPE_RPI_LIBCAMERA_OV9281` = **49**, in the ARDUCAM
  group of the camera list as "OV9281 (mono GS)".
- It uses the standard `ov9281` device tree overlay and libcamera's OV9281
  support (mono tuning for both the RPi 4 and the RPi 5 ISP), so boards from
  any vendor work the same way.
- The picture is grey. White balance and saturation have no effect.

| Mode            | Sensor mode                              |
|-----------------|------------------------------------------|
| 640x400 @60/120 | 2x2 binned, full field of view           |
| 1280x720 @60    | top 720 of the 800 sensor lines          |
| 1280x800 @30/60 | full sensor, 1280x800@60 is the default  |

## RPi 4 vs RPi 5

- RPi 4 / CM4: the HW H.264 encoder (`v4l2h264enc`) is used.
- RPi 5: there is no HW H.264 encoder, the stream is encoded with `x264enc`
  (`gstreamer1.0-plugins-ugly`). OpenHD also falls back to it on any RPi where
  `v4l2h264enc` is missing.
- The stock `libcamerasrc` on the RPi 5 has no OpenHD image settings
  (rotation, flip, brightness, ...), so OpenHD hides them there. For a camera
  mounted upside down, use `dtoverlay=ov9281,rotation=180`, libcamera then
  flips the sensor.
- OpenHD expects the RPi 5 as platform 13, like current OpenHD-SysUtils
  reports it.
- This OpenHD version only drives Wi-Fi cards with OpenHD's own Realtek
  kernel drivers (`rtl88xxau_ohd`, `rtl88x2bu_ohd`, `rtl88x2eu_ohd`). The
  OpenHD 2.6.4 kernel for the RPi 4 has them, no RPi 5 kernel does (OpenHD 3.0
  uses a user space driver instead), and there is no public OpenHD image for
  the RPi 5. So on the RPi 5 the camera works, but the link needs these
  drivers built for its kernel first.

## Outside this repository

Selecting the camera in QOpenHD makes OpenHD-SysUtils write the overlay to
`config.txt` and reboot. Both need to know camera type 49:

1. **OpenHD-SysUtils** needs a profile in `kProfiles`
   (`src/sysutil_camera.cpp`):

   ```cpp
   {49, "kms", "ov9281,arducam", false, nullptr},
   ```

   The `arducam` overlay parameter only adds a short regulator start-up delay,
   which slow Arducam modules need. Kernels before 6.6 (OpenHD 2.6.4) don't
   have it, the firmware then ignores it. Without this profile, OpenHD saves
   the camera type and reboots, but `config.txt` stays unchanged. Then add it
   by hand to `/boot/firmware/config.txt` (`/boot/config.txt` on Bullseye):

   ```
   camera_auto_detect=0
   dtoverlay=ov9281,arducam
   ```

   On the RPi 5, append `,cam0` if the camera is on the CAM0 connector.

2. **QOpenHD** has its own copy of the camera list
   (`app/telemetry/models/openhd_core/camera.hpp`): add type 49 with the modes
   above, list it for the RPi platforms, and set `X_PLATFORM_TYPE_RPI_5` to 13
   in `platform.hpp` so the RPi 5 gets a camera list. Until then, the camera
   can be preset with `"camera": "49"` in `openhd/settings.json` on the FAT
   partition (the file the OpenHD ImageWriter writes, OpenHD-SysUtils reads
   it as `/Config/openhd/settings.json` and then deletes it).

## Packages for the RPi 4

The `build_rpi_ov9281_update` workflow builds this branch for the RPi 4
(Bullseye armhf) and the RPi 5 (Bookworm arm64), together with
OpenHD-SysUtils main plus the profile above. Its postinst also enables the
`openhd-sys-utils` service, which only OpenHD-ImageBuilder images do
otherwise; without it, SysUtils doesn't start after a reboot and OpenHD runs
as ground without a camera.

The OpenHD 2.6.4 image (the newest one in the OpenHD ImageWriter) doesn't
install update packages by itself, so the `openhd-ov9281-rpi4` artifact has
the two .deb files and an `install.sh` for a one-time install:

1. Write "OpenHD-2.6.4-evo Raspberry" with the ImageWriter, copy the `ov9281`
   folder of the artifact into the `openhd` folder of the FAT partition.
2. Boot the Pi, wait for its first-boot reboots, log in (`openhd` /
   `openhd`, screen and keyboard or SSH).
3. `sudo bash /boot/openhd/ov9281/install.sh air` (or `ground`). It sets the
   role and camera 49 in `openhd/settings.json`, installs OpenHD, then
   OpenHD-SysUtils, which writes the overlay to `config.txt` and reboots.

The air unit and the ground station both need this build: its wifibroadcast
adds a header to every packet, which OpenHD 2.6.4 can't read. QOpenHD stays at
2.6.4 on the ground station, it doesn't list camera type 49.

## Check

`config.txt` has to end with `camera_auto_detect=0` and
`dtoverlay=ov9281,arducam`, and `dmesg | grep -i ov9281` must not show
probe errors. On Raspberry Pi OS Bookworm, `rpicam-hello --list-cameras`
(with OpenHD stopped) has to list an `ov9281` camera; the OpenHD 2.6.4 image
has no such tool. If the camera is missing, check the ribbon cable and the
connector.
